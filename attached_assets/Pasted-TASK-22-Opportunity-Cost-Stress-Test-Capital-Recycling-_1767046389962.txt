TASK 22 — Opportunity Cost Stress Test & Capital Recycling Validation

GOAL
Prove that the Capital Recycling Engine (Task 21) activates under realistic pressure
and that it *improves capital efficiency* rather than causing unnecessary churn.

This task is NOT about adding new strategy logic.
It is about forcing recycling scenarios, measuring outcomes, and validating that
capital is being reallocated from worse opportunities to better ones.

NO LOOKAHEAD GUARANTEE
- All decisions must use information available at or before entry.
- No future bars, future signals, or future MFE may be used in evaluation logic.
- Stress testing changes only *constraints*, not signal generation.

FILES TO MODIFY
- backtester.py
- metrics.py
- main.py
- optimize.py
- replit.md

──────────────────────────────────────────────────────────────────────────────
WHY THIS TASK EXISTS
──────────────────────────────────────────────────────────────────────────────
Task 21 added a powerful recycling engine, but:
- Demo universes rarely saturate budgets
- Recycling may not activate often in light scenarios
- Without pressure testing, we don’t know if recycling helps or hurts

Task 22 answers:
1) When recycling fires, does it replace worse capital with better capital?
2) Does recycling improve return per unit of deployed risk?
3) Is PARTIAL recycling superior to EXIT recycling?
4) Under what pressure conditions does recycling add value?

──────────────────────────────────────────────────────────────────────────────
PART 1 — Stress Test Modes
──────────────────────────────────────────────────────────────────────────────

Add stress-testing options to BacktestConfig:

    # Stress test controls
    recycling_stress_mode: str = "NONE"
        # NONE
        # LOW_BUDGET
        # HIGH_SIGNAL_DENSITY
        # BOTH

    recycling_stress_daily_budget_mult: float = 0.50
        # Applied when stress mode includes LOW_BUDGET

    recycling_stress_disable_topk: bool = True
        # Disable top_k_per_day / week limits to increase congestion

    recycling_stress_start_date: Optional[str] = None
    recycling_stress_end_date: Optional[str] = None
        # If set, apply stress only during this window

Behavior:
- Stress mode modifies only portfolio constraints
- Signal detection, scoring, and sizing remain unchanged
- Must be reversible and deterministic

──────────────────────────────────────────────────────────────────────────────
PART 2 — Stress Logic Implementation (backtester.py)
──────────────────────────────────────────────────────────────────────────────

In run_backtest():

1) Determine if stress mode is active for current_date
2) If LOW_BUDGET:
   - effective_daily_budget = daily_risk_budget * recycling_stress_daily_budget_mult
3) If HIGH_SIGNAL_DENSITY:
   - Temporarily ignore max_signals_per_day
   - Ignore top_k_per_day / top_k_per_week caps
4) If BOTH:
   - Apply both behaviors simultaneously

Ensure:
- Stress-adjusted budgets are used ONLY for allocation decisions
- Report both base and stressed budgets in diagnostics

PART 3 — Recycling Effectiveness Metrics
──────────────────────────────────────────────────────────────────────────────

Extend metrics.py with:

compute_recycling_effectiveness_metrics(trades_df):

For each recycling event:
- Identify:
  - recycled_trade_id
  - replacing_trade_id (triggering candidate)
- Compute:
  - recycle_swap_edge_r =
        replacing_trade_r_multiple
      - remaining_r_multiple_of_recycled_trade
  - capital_reuse_efficiency =
        incremental_return / freed_risk_fraction

Aggregate metrics:
- recycle_events_count
- pct_trades_recycled
- avg_swap_edge_r
- median_swap_edge_r
- pct_positive_swaps
- avg_capital_reuse_efficiency
- false_recycle_rate
    (recycled trade would have outperformed replacement)

Output:
outputs/recycling_effectiveness_report.csv
