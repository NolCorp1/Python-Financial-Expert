TASK 20 — Portfolio Capital Allocation & Signal Competition Engine

GOAL
Introduce a portfolio-level capital allocation system so that signals compete for a finite daily/weekly risk budget.
This ensures capital is concentrated in the highest-quality opportunities and prevents over-allocation during signal clusters — without adding lookahead or changing signal generation logic.

This task upgrades the system from “independent trade sizing” to a true portfolio allocator.

──────────────────────────────────────────────────────────────────────────────
WHY THIS MATTERS (CONTEXT)
──────────────────────────────────────────────────────────────────────────────
Up to Task 19, position sizing is:
- Signal-local
- Score-aware
- Regime-aware

But still:
- Capital is allocated per trade, not per opportunity set
- Multiple mediocre signals can crowd out elite setups
- Drawdowns increase when many signals fire together

Task 20 introduces:
- Finite risk budgets
- Signal competition
- Proportional scaling when demand > supply

This is a *structural* edge, not new alpha.

──────────────────────────────────────────────────────────────────────────────
HIGH-LEVEL BEHAVIOR
──────────────────────────────────────────────────────────────────────────────
For each trading day:

1) Collect all candidate signals eligible for entry
2) Rank them by quality / expected edge proxy
3) Allocate capital subject to:
   - Daily total risk budget
   - Optional weekly budget
   - Optional per-kind budgets (FORMING vs CONFIRMED)
4) If total requested risk > budget:
   - Scale positions proportionally
   - Preserve relative conviction
5) Record allocation diagnostics for analysis

All logic uses ONLY pre-entry information (no lookahead).

PART 2 — Signal Ranking Metric
──────────────────────────────────────────────────────────────────────────────

Add helper function (top-level in backtester.py):

def compute_signal_allocation_score(signal) -> float:
    """
    Ranking score for capital allocation.
    Uses only pre-entry data.
    """
    score = 1.0

    if signal.meta:
        ps = signal.meta.get("pattern_score")
        sr = signal.meta.get("score_risk_mult", 1.0)
        rr = signal.meta.get("regime_risk_mult", 1.0)

        if ps is not None:
            score *= ps / 100.0

        score *= sr
        score *= rr

    # Prefer CONFIRMED slightly by default
    if signal.entry_kind == "CONFIRMED":
        score *= 1.10

    return float(score)

This metric must be:
- Deterministic
- Monotonic in quality
- Pre-entry only

PART 3 — Backtester: Capital Allocation Engine
──────────────────────────────────────────────────────────────────────────────

In run_backtest():

A) Before processing entries on a given date:
- Gather all signals whose entry_date == current_date
- Filter by existing constraints (correlation caps, cluster caps, max positions)

B) If use_portfolio_allocator is True:

1) Compute requested risk per signal
   requested_risk = equity × risk_fraction_applied

2) Group signals:
   - All
   - FORMING
   - CONFIRMED

3) Determine applicable budgets:
   - daily_risk_budget
   - daily_risk_budget_forming (if set)
   - daily_risk_budget_confirmed (if set)

4) Rank signals by compute_signal_allocation_score()

5) If max_signals_per_day is set:
   - Keep only top-N ranked signals

6) Allocation logic:
   - Sum requested_risk across selected signals
   - If <= budget → accept all
   - If > budget:
       - Compute scale = budget / total_requested
       - If scale < min_allocation_scale:
           - If allocation_scaling_mode == HARD_CUTOFF:
               - Take top signals until budget exhausted
           - Else:
               - Clamp scale to min_allocation_scale
       - Multiply each signal’s risk_fraction_applied by scale

7) Apply scaled risk_fraction_applied to position sizing

C) Store allocation metadata in signal.meta:
    - allocation_score
    - allocation_scale
    - allocation_budget_used
    - allocation_rank
