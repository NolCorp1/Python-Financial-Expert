Task 1 — Pattern Output Hardening (Forming + Confirmed Metadata)
==============================================================================
Objective
---------
Make `double_bottom_scanner.py` produce strategy-ready pattern records for BOTH
FORMING and CONFIRMED patterns with a consistent schema and deterministic IDs.

This task does NOT change detection thresholds/logic materially; it only:
- standardizes output fields
- adds a "forming trigger level" used later for early-entry logic
- ensures the scan CSV contains all required columns


Files to Edit
-------------
- double_bottom_scanner.py

3) Add forming trigger computation (v1)
---------------------------------------
After Bottom2 is identified (index i2 in the scan window), compute a simple,
robust trigger level that can be used later for early entry.

Definition (v1):
- Use the maximum High over the next `trigger_lookahead_days` bars after Bottom2.
- If there are not enough bars available, return None.

Add this helper function to `double_bottom_scanner.py` (top-level, near other
helpers). Make sure it works with your local df index/iloc usage.

Add:

    def compute_forming_trigger_level(
        df: pd.DataFrame,
        bottom2_pos: int,
        trigger_lookahead_days: int = 10
    ) -> tuple[float | None, str]:
        """Return (forming_trigger_level, reason).

        v1 rule:
          forming_trigger_level = max(High[bottom2_pos+1 : bottom2_pos+1+trigger_lookahead_days])
        """
        start = bottom2_pos + 1
        end = min(bottom2_pos + 1 + trigger_lookahead_days, len(df))
        if start >= end:
            return None, "insufficient_bars_after_bottom2"
        level = float(df["High"].iloc[start:end].max())
        if not (level > 0):
            return None, "invalid_trigger_level"
        return level, f"max_high_next_{end-start}_bars_after_bottom2"


Then, when building each pattern record, set:

- avg_bottom = (bottom1_price + bottom2_price) / 2.0
- height = neckline - avg_bottom
- separation_days = (i2 - i1)              # trading-bar separation
- forming_trigger_level, forming_trigger_reason = compute_forming_trigger_level(...)

IMPORTANT:
- Always include forming_trigger_* fields, even for CONFIRMED patterns.
  (They are still useful for analysis.)

-------------------
A) Running a scan produces a CSV where EACH row has:
   - status in {"FORMING", "CONFIRMED"}

   - breakout_date column present (blank/NaN for forming patterns)

D) Forming patterns still behave the same:
