TASK 29 — Paper Trading Reporting & Performance Attribution
==========================================================

OBJECTIVE
---------
Build a daily + weekly reporting and attribution layer for the paper trading system that converts raw paper trading runs into decision-quality feedback.

This task MUST NOT modify:
- Trading logic
- Signal generation
- Capital recycling behavior
- Portfolio state mutation rules

This task is strictly observational, aggregative, and explanatory.

WHY THIS TASK EXISTS
--------------------
At this stage the system already has:
- Deterministic backtests
- Capital recycling with quality gates
- Stress-tested robustness
- A fully idempotent paper trading loop

What is missing is institutional-grade visibility:
- Are FORMING trades helping or hurting?
- Is recycling improving outcomes over time?
- Are score buckets behaving in paper as in backtest?
- Is exposure evolving safely?

This task upgrades paper trading from “it runs” to “we understand it.”

This is REQUIRED before live trading approval.

SCOPE OF WORK
-------------

PART A — Daily Paper Report Enhancements
----------------------------------------
Extend the report.md generated by scripts/run_paper_daily.py.

Add the following sections:

1) Portfolio Snapshot
- Starting equity
- Ending equity
- Daily PnL ($ and %)
- Cash vs invested capital
- Open positions count
- FORMING vs CONFIRMED open positions

2) Exposure Summary
- Exposure by symbol
- Exposure by cluster (if cluster caps enabled)
- Largest single-position % of equity

3) Recycling Summary (if enabled)
- Recycling events today
- Capital freed ($ and %)
- Average swap edge (R)
- Blocked vs accepted recycling attempts

4) Signal Intake Summary
- Total signals generated
- Signals skipped (by reason)
- Signals accepted
- FORMING vs CONFIRMED split

All numbers must be derived from paper trading outputs and portfolio state.
No randomness allowed.

PART B — Weekly Aggregation Report
----------------------------------
Add a new script:

scripts/generate_paper_weekly_report.py

Inputs:
- outputs/paper/YYYYMMDD/ directories
- paper_portfolio.json snapshots
- orders.csv
- orders.json

Outputs:
outputs/paper/weekly/YYYY-WW/
  - weekly_report.md
  - equity_curve.csv
  - exposure_timeseries.csv
  - recycling_timeseries.csv

Weekly metrics to compute:
- Weekly return %
- Max intraweek drawdown
- Average daily exposure
- Trades opened
- Trades closed
- Recycling KPIs:
  - recycle events
  - average swap edge
  - false recycle rate
- FORMING vs CONFIRMED performance split

PART C — Attribution Tables
---------------------------
Generate the following CSV files:

1) performance_by_entry_kind.csv
Columns:
- entry_kind
- trades
- win_rate
- avg_r
- total_r

2) performance_by_score_bucket.csv
Columns:
- score_bucket
- trades
- avg_r
- win_rate

3) recycling_attribution.csv
Columns:
- recycle_date
- victim_symbol
- replacement_symbol
- victim_r_at_recycle
- replacement_r
- swap_edge_r

These CSVs must be suitable for later dashboards and audits.

PART D — Determinism & Idempotence
----------------------------------
- Weekly reports must be purely derived artifacts
- No timestamps in numeric outputs
- Re-running the same weekly report produces identical files
- SHA256 hashes must match on repeat runs

ACCEPTANCE CRITERIA
-------------------

Functional:
- Daily paper report includes all new sections
- Weekly aggregation script runs successfully
- Attribution CSVs generated correctly

Safety:
- No changes to trading logic
- No changes to order generation
- No changes to portfolio mutation

Determinism:
- Weekly report re-runs produce identical SHA256 hashes
- No nondeterministic ordering or floating drift

Validation:
Provide commands such as:
python scripts/generate_paper_weekly_report.py --week 2024-W09
sha256sum outputs/paper/weekly/2024-W09/*.csv

OUT OF SCOPE (DO NOT IMPLEMENT)
------------------------------
- Dashboards
- Plotting or charting
- Broker or live trading integration
- ML models
- Signal changes

DELIVERABLES CHECKLIST
----------------------
- Enhanced daily report.md
- Weekly aggregation script
- Attribution CSV outputs
- Deterministic behavior verified
- Documentation updated in replit.md

FINAL INSTRUCTION TO AGENT
--------------------------
Implement Task 29 exactly as specified.
Preserve determinism, idempotence, and all existing behavior.
Treat paper trading outputs as audit-grade artifacts.
