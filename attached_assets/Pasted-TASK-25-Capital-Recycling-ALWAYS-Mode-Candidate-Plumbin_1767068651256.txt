PART A — Capture Constraint-Blocked Signals (Missing Plumbing)
============================================================

Locate all places in backtester.py where trade candidates are skipped due to hard constraints, including but not limited to:
- Max total positions
- Max FORMING positions
- Cluster caps
- Correlation caps
- Symbol already open

Currently these skips only increment skip counters and discard the candidate.
This is incorrect for ALWAYS recycling mode.

Implement a blocked signal accumulator:

- Initialize `blocked_signals = []` at the start of each trading day
- Whenever a candidate is skipped due to a HARD constraint, append a structured record:

{
    "date": current_date,
    "symbol": candidate.symbol,
    "score": candidate.score,
    "stage": candidate.stage,  # FORMING or CONFIRMED
    "reason": "<CONSTRAINT_REASON>",
    "risk_needed": candidate.risk_budget,
    "meta": {
        "cluster_id": candidate.cluster_id (if available)
    }
}

This must be done for ALL non-budget constraint skips.

PART C — Fix Guard Logic That Silently Blocks Recycling
============================================================

Audit and correct the following common failure modes:

1) Score gap guard
If recycle-min-score-gap == 0, recycling must NOT be blocked.
Ensure comparisons use:
    gap < min_gap   (NOT <=)

Ensure logic correctly interprets these values as disabling conditions.

3) Constraint re-validation order

- First simulate removing the position being recycled
- Then validate constraints against:
    (open_positions - removed_position) + new_candidate

Do NOT validate against the original open set before removal.
